# AI 运维机器人：权限与行动面分析（通用版）

> 适用：对话入口（如 Lark）+ MCP 多系统接入的 AI 运维 / 诊断 Agent  
> 说明：下文以「代码库未授权读取 + 打包外发」为个案引子，结论与 Action 均为通用原则

---

## 1. 案例摘要（抽象）

组织部署了对话驱动的 AI 运维机器人，经 MCP 接入观测、云、容器编排、代码托管、运维平台等多类系统，承担查询 / 诊断 / 分析等职责。

**个案表现（仅作引子）：**

- 人对代码仓库有严格 ACL，但经机器人仍获取到非授权仓库内容
- 对话可触发「读取 → 打包 → 上传外网 → 匿名下载链接」类能力

**通用本质：**

Agent 未按终端用户身份约束行动，高危能力与低摩擦对话入口未隔离，导致人侧权限模型在 Agent 路径上失效。

---

## 2. 通用问题分析

| # | 问题 | 说明 |
|---|------|------|
| 1 | 混乱代理人（Confused Deputy） | 工具按 Bot 服务身份鉴权，而非终端用户身份 → 人的 ACL 被绕过 |
| 2 | 权限模型错误 | 宽权限服务号 + 对话任意触发 → 爆炸半径从「用户可见范围」放大到「Bot 能访问的一切」 |
| 3 | 能力分级缺失 | 只读探测、写变更、数据出境、跨租户查询等混挂在同一 Agent / 同一会话 |
| 4 | Harness / 策略引擎缺失 | 无强制门禁（身份下行、白名单、审批、审计）；仅靠 Prompt 约束无效 |
| 5 | 入口信任过高 | IM 对话指令被直接当作已授权的取数 / 变更请求 |

> 个案映射：未授权读仓 = 问题 1/2；打包外发匿名链接 = 问题 3/4 在「数据出境」类动作上的实例。同类风险可出现在日志导出、配置拉取、工单附件外发、跨环境查询等任意高危动作上。

---

## 3. 能力分级（建议）

| 级别 | 类型 | 示例 | 对话态默认策略 |
|------|------|------|----------------|
| L0 | 无害只读 | 查公开文档、百科式说明 | 可自动 |
| L1 | 授权范围内只读探测 | 查指标 / 日志 / 资源描述（受用户 ACL 约束） | 可自动，强审计 |
| L2 | 写变更 / 产生影响 | 重启、改配置、扩缩容、提单工单状态 | 默认拒绝；审批后短时放开 |
| L3 | 数据出境 / 批量导出 / 跨租户 | 打包外发、匿名链接、全量导出、跨账号读取 | 默认禁用；独立变更流程 + 双人审批 |

原则：**诊断对话默认最多到 L1；L2/L3 不得与诊断 Agent 同进程默认挂载。**

---

## 4. 改进 Action（通用）

### P0（立即）

1. **身份下行**：所有 MCP / API 调用绑定终端用户身份（或「用户权限 ∩ Bot 权限」），禁止万能服务号代表任意用户读写。
2. **工具分级 + 默认拒绝**：按上表分级；L2/L3 从对话诊断 Agent 卸载或默认不可调用。
3. **高危通道拆分**：写变更、出境、批量导出走独立审批流，不与日常诊断会话混用。

### P1（短期）

4. **策略引擎硬闸**（非 Prompt）：校验「动作类型 × 环境 × 对象范围 × 用户 ACL」，失败则短路拒绝。
5. **统一审计与回放**：记录谁、何时、对何资源、以何身份发起了何次 tool_call；支持越权排查。
6. **入口约束**：限制可调用人 / 群 / 环境；高危意图转工单，不直接执行。

### P2（持续）

7. **最小暴露**：按域拆分凭证与网络出口；敏感路径 / 字段脱敏与黑名单。
8. **门禁回归验证**：固定用例「低权用户请求高权资源 / 出境动作」必须失败；防止权限回潮。

---

## 5. 一句话结论

通用解法是 **用户身份下行 + 工具分级隔离 + 策略硬闸 + 审计**；  
「未授权读仓并外发」只是错误权限模型下 **L3 数据出境** 的一个实例，同类问题会在任何未按用户 ACL 约束的工具上重复出现。

# 侧轨 P · 私有化推理起步（Private Deploy）

> 启动点：Stage 1 末 · 汇合点：Stage 6 推理平台  
> 目标深度：L2（能跑通、能量化、能讲清边界），不做训练研究

## 1. 为什么现在就开始

框架约束：**私有化尽早**。Stage 1 已建立 Token/API/成本语感后，用最小闭环验证「自建是否可行」，避免纸上谈兵。

## 2. 最小技术地图

```text
本地试验                准生产
Ollama  -------------->  vLLM / TGI 等
   \                      /
    \--> OpenAI-compatible Gateway (鉴权/路由/审计)
              |
         现有可观测栈 (metrics/logs/traces)
```

| 组件 | 本阶段用途 |
|------|------------|
| Ollama | 笔记本/单机快速拉模型、验证 API 形状 |
| vLLM | 更高吞吐与批处理；更接近平台形态 |
| OpenAI-compatible 网关 | 把多模型（含云 API）统一成一种客户端契约 |
| 观测 | QPS、TTFT、错误率、GPU 利用率、每请求 token |

## 3. Stage 1 末最小实验（无 GPU 也可做一部分）

### P0 · 契约对齐（可纯云上对照）

1. 用同一客户端分别打云 API 与（若有）本地兼容端点
2. 核对：`messages` 角色、`usage` 字段、流式 SSE 行为差异
3. 记录「不兼容点清单」—— 这是未来网关要抹平的东西

### P1 · Ollama 单机（有本地资源时）

```bash
# 示意：按你机器与镜像源调整
ollama pull <small-model>
curl http://localhost:11434/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"<small-model>","messages":[{"role":"user","content":"ping"}]}'
```

观察：冷启动、显存/内存占用、并发 1 vs 4 的退化曲线。

### P2 · 决策备忘（写进变更评审话术）

对每个候选模型回答：

1. 许可是否允许内网服务化与商业使用？
2. 上下文长度是否覆盖你们 SOP/日志场景？
3. 工具调用 / JSON mode 可靠吗？
4. 量化后质量掉多少？（用 E1 同款 T1 复测）

## 4. 与轴 C 的挂钩（别做成玩具）

即使是侧轨实验，也强制带上：

- **SLO 草案**：可用性、P99 TTFT、错误预算
- **租户隔离**：至少进程级；后续网络策略/沙箱
- **成本账本**：GPU 小时 vs 云 API token 账单对照模板

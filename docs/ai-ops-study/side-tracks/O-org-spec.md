# 侧轨 O · 虚拟小团队规格（Org Spec / SDD）

> 启动：现在写规格 · 可执行化：Stage 3 Agent + Harness  
> 目的：组织与流程作为 **独立轴 D**，不是应用代码附属品

## 1. 虚拟小团队（默认草案）

假设一个「AI 辅助值班 + 变更」小队（可按你的真实组织改名）：

| 角色 | 职责 | 可否自动 | 人工门禁 |
|------|------|----------|----------|
| Triage Agent | 告警归类、捞日志摘要、提出假设 | 是 | 高风险操作前停 |
| Runbook Agent | 匹配 SOP、生成检查清单 | 是 | 修改生产前停 |
| Change Agent | 起草变更单、回滚方案 | 是 | **必须**人工批准 |
| Knowledge Curator | 沉淀复盘进知识库 | 半自动 | 发布前人工审 |
| Human Oncall | 最终责任、例外决策 | 否 | — |

## 2. 知识边界

| 知识域 | 读权限 | 写权限 | 备注 |
|--------|--------|--------|------|
| 公开 Runbook | 全员 Agent | Curator + Human | |
| 客户数据 / 密钥 | 禁止进提示词 | — | 只通过工具在沙箱触达 |
| 变更历史 | Oncall + Change Agent | 系统审计日志 | 不可由模型改写历史 |

## 3. 人工门禁（最小集合）

1. 任何 `apply` / 重启 / 扩缩容 / 删资源
2. 任何密钥与生产配置读取（若允许，也需审计）
3. 对外发送（邮件/工单公众回复）
4. 知识库「正式发布」

门禁协议（Stage 3 再绑到 Harness）：

```text
Agent proposal
  -> policy check (角色/权限/环境)
  -> human approval (超时策略、升级策略)
  -> execute in sandbox or prod
  -> append audit event
```

## 4. SDD 模板（持续填）

```markdown
## 场景名
## 触发条件
## 参与角色
## 输入 / 输出契约
## 允许工具列表
## 禁止事项
## 成功标准
## 失败与升级
## 审计字段
```

建议先写 2 个场景：`告警初判`、`变更草案`。

## 5. 与学习主路径的接口

- Stage 2：知识库/RAG/权限落到「知识边界」表
- Stage 3：本 SDD 变成可执行 Agent 图与审批流
- 全程：E1 等多模型结论影响「默认模型路由」策略（组织决策，不是个人口味）

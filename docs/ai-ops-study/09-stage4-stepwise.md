## 4.1 训练 vs 推理：你站在哪一边

### 一句话

| | 训练 Training | 推理 Inference |
|--|----------------|----------------|
| 目的 | **改**模型权重，让它变「会」 | **用**已固定的权重生成输出 |
| 过程 | 前向 → 算损失 → 反向传梯度 → 优化器更新参数 → 反复 | 前向 → 采样 token → 循环（权重不动） |
| 成本形态 | 长周期、大数据、极吃显存 | 按请求持续跑，吃算力/带宽/KV/并发 |
| 谁在做 | 模型实验室、少数平台团队 | API、私有化部署、你的运维机器人后端 |

### 为什么先分清

Stage 1 里「分词 → 前向 → 采样」描述的是 **推理**。  
Stage 4 整章默认站在推理侧：容量、SLO、OOM、量化——都是推理词。  
训练只需要知道「存在、更贵、多数企业不自训基座」，避免概念串台。

### 和你场景的挂钩

- Claude / Kimi / DeepSeek API、本地 Ollama/vLLM：**推理服务**
- AI 运维机器人每次对话与 tool 回写：**一次次推理请求**
- 权限与 Harness：组织问题；不改变「底层仍是推理」这一事实

### 本步只记

**训练改权重；推理用权重。运维主场是推理。**

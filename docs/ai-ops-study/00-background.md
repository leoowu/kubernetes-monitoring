## 1. 职业与能力底盘

- **角色**：资深系统运维工程师（SRE / Platform Ops）
- **强项**：Linux、容器、沙箱、微服务熔断、可观测、容量与成本、IaC/CI、分层排障
- **学习态度**：AI 日用重度用户；目标是系统性理解机制，并能深入到深度学习网络层（不等于转算法岗）

## 3. 趋势判断 / 假设

1. **私有/本地部署趋势**：当开源或国内模型质量跨过阈值，大量企业会因数据安全、合规、成本、可控性选择自建部署。
2. **「KM 模型」释义（待确认）**
   - 假设 A：可私有部署的开源/国内模型族（如 Kimi、DeepSeek）
   - 假设 B：某特定厂商/代际模型
   - **当前决策**：计划暂按假设 A 推进

---

## 4. 中长期方向 / 北极星

不止做「prompt 用户」，而是建设 **AI 原生组织形态与支撑系统**。

能力支柱：

1. **AI 组织/编排**：人机协作、角色、审批流
2. **知识库**：组织记忆、检索、权限
3. **流程体系**：SOP 与可执行 Agent 流水线
4. **功能平台**：模型路由、私有部署、工具/MCP、可观测

与运维的交汇（差异化入口）：私有部署、推理平台、沙箱、SLO/成本、可观测 —— 相对纯应用开发者的优势落点。

---

## 5. 对学习系统的约束

由背景导出的硬规则：

1. **机制优先**：学 Token / Transformer 是为了设计系统与平台，不是算法职业路径。
2. **多模型一等公民**：Claude / Codex / Kimi / DeepSeek 对照必须是主线实验，不能是附录。
3. **私有化尽早**：不要拖到最后才学 model serving。
4. **独立轴**：组织与流程必须作为独立轨道（轴 D），不能只是应用代码的附属。

# E1 · 四模型对照实验协议

> 对齐 Stage 1：Claude / Codex / Kimi / DeepSeek  
> 原则：可复现、可计量、可归档进组织知识库

## 1. 实验目的

在相同任务下比较四模型的 **质量 / token / 延迟 / 失败模式**，产出选型基线，而不是主观偏好。

## 2. 固定条件（自变量控制）

| 项 | 规定 |
|----|------|
| 任务说明书 | 同一份 Markdown，禁止按模型改写提示「讨好」 |
| 系统提示 | 同一套；若某模型无 system 角色，拼进首条 user |
| 温度等采样参数 | 尽量对齐；无法对齐时在表中注明默认值 |
| 超时 | 统一（建议 60s 首 token / 180s 总时长，可按环境改） |
| 重试 | 仅网络/5xx；业务错误不重试 |
| 工具 | 第一轮 **关闭工具**（测纯生成）；第二轮再开同一工具集 |
| 日期 | 记录运行日，避免「模型静默升级」无法对比 |

## 3. 推荐任务集（先做 T1，再扩展）

| ID | 任务 | 为何适合运维学习者 |
|----|------|---------------------|
| T1 | 根据一段虚构的 `kubectl describe pod` 输出，给出分层排障假设与下一条命令 | 你有真领域知识，易打质量分 |
| T2 | 把一段混沌的告警文案改写成「现象 / 影响 / 假设 / 验证」四段 | 测指令遵循与结构 |
| T3 | 设计一个 OpenAI-compatible 网关的最小 SLO（可用性、延迟、错误预算） | 测平台思维，非背诵 |
| T4 | （可选）给定错误的「假装已执行」工具叙事，识别并拒绝 | 测工具幻觉边界 |

每任务准备：

- `prompt.md`：完整输入
- `rubric.md`：评分细则（0–5）
- `golden-notes.md`：参考要点（非唯一答案）

## 5. 质量评分量规（T1 示例）

| 分 | 标准 |
|----|------|
| 5 | 分层正确、假设可证伪、下一条命令可执行且安全 |
| 4 | 主路径对，次要细节小瑕疵 |
| 3 | 有用但不完整或有一处危险建议 |
| 2 | 表面正确、关键误判 |
| 1 | 明显幻觉或危险操作 |
| 0 | 拒答/崩溃/完全跑题 |

建议：同一答卷由你盲评一次；隔日再评一次（测自评稳定性）。

## 6. 分析问题（写进结果文末）

1. 谁在「短上下文排障」上性价比最高？
2. 国内模型在指令遵循上是否已够用作为私有化候选？
3. 哪类失败模式会在生产里变成事故（优先加门禁）？
4. 若只允许两个默认路由，你选哪两个？为什么？

## 7. 安全与合规

- 实验输入使用 **虚构/脱敏** 数据，不把真实客户日志贴进公有云模型
- 若必须用真实片段：优先可私有部署模型或本地 Ollama（侧轨 P）

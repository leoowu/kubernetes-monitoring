## 5.1 注意力在解决什么问题

### 旧问题（直觉）

早期序列模型（如经典 RNN）大体是：从左到右一步步读，把历史压进一个隐状态。  
长距离依赖难：开头的约束传到结尾容易「淡掉」。

### Transformer 的核心一手

**注意力（Attention）**：生成或编码某个位置时，不靠单一压缩记忆，而是 **直接回看序列里其它位置，按相关性加权取信息**。

对 LLM 解码（生成下一个 token）而言，直觉是：

> 我现在要写下一个词，就在已有 token 里查：哪些位置和我现在最相关，多看它们一点。

### 和你已有知识的对接

```text
Stage 1：分词 → 前向 → 采样
Stage 4：前向里尽是层与矩阵乘
Stage 5.1：这些层里，最关键的一种叫「注意力」——负责「看哪里」
```

还不必记公式。先记住分工：

| 部件 | 负责 |
|------|------|
| 注意力 | 从上下文里选信息、对齐关系 |
| 前馈网络（FFN） | 对当前位置做非线性变换（「思考/映射」） |
| 采样 | 从词表分数里挑下一个 token |

### 运维为何要关心

注意力要在序列长度上两两交互（实现上常配合 KV Cache），所以：

- 上下文越长 → 算力与显存压力越大（后面 5.4 展开）  
- 「窗口」不是营销词，是注意力能有效回看的范围上限  

### 本步收束

**注意力 = 动态地决定「当前计算该看上下文的哪些部分」。**  
这是 Transformer/LLM 相对「只能顺序压缩记忆」的关键升级。

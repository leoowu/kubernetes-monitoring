# Stage 0 · 坐标系：北极星 / OSI / 六层 / 四轴

## 1. 本课目标

把「学什么、为什么学、运维切入点在哪」钉死成一张图，避免后续沦为散点 prompt 技巧课。

验收标准：

1. 能用一句话复述北极星（不是「会用 ChatGPT」）
2. 能指出任意新概念落在哪一层、哪一轴
3. 能说出运维相对应用开发的差异化入口（平台 C + 组织 D）

---

## 2. 北极星（North Star）

**建设 AI 原生组织形态与支撑系统**：人机协作编排 + 组织知识库 + 可执行流程 + 功能平台（路由/私有化/工具总线/可观测）。

反例（明确不做为终点）：

- 只收集 prompt 模板
- 只追模型榜单分数
- 只做单次 Demo Agent，没有审批/权限/SLO

---

## 3. 对照图：OSI × AI 六层 × 四轴

```text
┌──────────────────────────────────────────────────────────────┐
│  北极星：AI 组织 / 知识库 / 流程 / 平台                         │
└──────────────────────────────────────────────────────────────┘

组织与体系 (轴 D) ─── 角色 · 审批门 · SOP · Harness ─── Stage 3+
        ▲
应用工程 (轴 A) — AI 技术栈六层（自上而下）
  L6  体验 / 体验层          产品形态、人机界面、工作台
  L5  Agent / 工作流层       规划、工具调用、多步闭环
  L4  RAG / 记忆 / 权限      组织知识、检索、ACL
  L3  编排 / 路由 / 网关     多模型路由、限流、审计
  L2  模型 API 接口层        Chat Completions、流式、工具协议
  L1  Token / 上下文物理层   分词、窗口、计费单位、截断
        ▲
模型机制 (轴 B) ── Transformer / 训练-推理 / 许可 ── Stage 4–5
平台运维 (轴 C) ── Serving · GPU · SLO · 成本 · 沙箱 · Observability
        ▲
侧轨 P（私有化）可从 Stage 1 末并行爬升至 Stage 6 汇合
```

与经典 OSI 的类比（帮助记忆，不是严格等价）：

| OSI 直觉 | AI 栈对应 |
|----------|-----------|
| 物理/数据链路 | Token、上下文、KV cache、显存带宽 |
| 网络/传输 | API、流式、重试、超时、幂等 |
| 会话 | 对话状态外置（服务端无状态） |
| 表示 | Prompt / Schema / Tool JSON |
| 应用 | Agent、知识库、审批流、业务 SOP |

## 4. 运维交汇点（你的差异化）

| 交汇点 | 为何是运维优势 | 对应轴/Stage |
|--------|----------------|--------------|
| 私有推理与网关 | 容量、隔离、升级、回滚 | C / 侧轨 P / 6 |
| 沙箱与工具权限 | 与容器、网络策略同构 | C + D / 3 |
| SLO / 延迟 / 错误预算 | 把 LLM 当生产依赖 | C / 1–6 |
| 成本与配额 | token 与 GPU 小时双账本 | C / 1+ |
| 可观测 | prompt/trace/eval 接入现有观测栈 | C / 2–3 |
| 审批与变更门禁 | 对齐变更管理与值班 | D / 3 |

## 5. 最小自检（10 分钟）

对下列说法判断对错并改写：

1. 「学 Transformer 是为了自己训练 SOTA 模型」→ **错**。改为：为了读懂上下文/许可/serving 约束，以便设计平台。
2. 「私有化放到最后再学」→ **错**。侧轨 P 在 Stage 1 末启动。
3. 「多模型对照是选修」→ **错**。Claude/Codex/Kimi/DeepSeek 是一等公民实验。
4. 「组织流程等产品做完再补」→ **错**。轴 D 独立，Stage 3 可执行化。

# Stage 4 · DL 基础（机制向）

> 目标深度：L2（能读懂训练/推理在算什么、贵在哪），不为转算法岗。  
> 上承：Stage 1 的「分词 → 前向 → 采样」。  
> 下接：Stage 5 Transformer/LLM；侧轨 P / Stage 6 推理平台。

## 1. 为什么运维要懂一点 DL

不是为了手写反向传播，而是为了：

- 读懂显存、算力、batch、精度为何影响 **SLO 与成本**
- 区分 **训练** vs **推理**（你的私有化主战场是推理）
- 和算法/平台同学用同一套词谈容量与故障

---

## 2. 最小对象：张量、层、网络

| 概念 | 一句话 |
|------|--------|
| 张量 Tensor | 多维数组（标量/向量/矩阵的推广），GPU 上的基本数据形态 |
| 参数 / 权重 | 网络里可学习的数字；LLM「多大」主要指参数量 |
| 层 Layer | 一种变换：输入张量 → 输出张量 |
| 网络 | 多层堆叠；LLM 是「很深 + 很宽」的堆叠 |

推理时：权重已冻住，只做前向；训练时：还要算损失、反向更新权重。

---

## 3. 训练在干什么（只需到这）

```text
数据 → 前向得到预测
     → 损失（离正确答案多远）
     → 反向传播（各参数对损失的梯度）
     → 优化器按梯度改权重
     → 重复
```

对你有用的推论：

- 训练极贵、极吃显存（激活 + 梯度 + 优化器状态）
- 多数企业 AI 运维平台 **不自训基座**，而是部署/微调已有模型
- 「微调 / LoRA」= 改少量参数或旁路参数，仍属训练家族，但比全量训练轻

---

## 4. 推理在干什么（你的主场）

回到 Stage 1，并补上硬件视角：

```text
token ids
  → Embedding（查表成向量）
  → 一层层计算（矩阵乘 + 非线性等）
  → Logits
  → 采样下一个 token
  → 循环
```

贵在：

1. **矩阵乘**（算力 / FLOPs）  
2. **显存带宽**（搬权重、搬 KV cache）  
3. **KV cache 随上下文与并发增长**（容量规划核心）

指标对应：

| 现象 | 常见原因 |
|------|----------|
| TTFT 高 | prefill（整段 prompt 首次前向）重 |
| 生成越往后越慢/吞吐掉 | 上下文变长，cache 变大 |
| OOM | 权重大 + cache + 并发过高 |
| 降精度（FP16/INT8/INT4）后变快变省 | 权重与激活更小，可能损质量 |

---

## 5. 过拟合 / 泛化 / 幻觉（直觉级）

- **过拟合**：死记训练样本，换场景差  
- **泛化**：没见过的输入也能用  
- **LLM 幻觉**：采样在「像真的分布」里取了错事实——不是「坏了的过拟合」一词能概括，但同属 **不能当真理源**；故 Stage 2 要 RAG/工具验真  

---

## 6. 和你机器人案例的挂钩

诊断 Agent 不需要自训模型；你要懂的是：

- 每次 tool 结果进 prompt → **prefill 变贵**（Stage 1+4）  
- 私有化选型要看参数量、上下文、量化后质量（侧轨 P）  
- 权限问题是 Harness，不是 DL——但「模型会编」强化了必须验真与门禁  

## 7. 心智模型

**训练改权重；推理用权重。**  
运维主战场是推理：算力、显存、KV cache、精度、并发与 SLO。
